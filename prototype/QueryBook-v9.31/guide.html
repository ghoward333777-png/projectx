QueryBook User Guide

QueryBook is a fact-harvesting answer engine that cannot state a fact it did not retrieve and verify. Every answer traces to a stored Fact Unit with a source, a trust score, and a fingerprint; when nothing is verified, it refuses instead of guessing. This guide covers everything the running app can do today, and flags clearly what is on the roadmap.

Legend. Built works in the app right now   Roadmap specified, refuses rather than fabricate   Planned UI stub / illustrative

What QueryBook is Built

QueryBook stores knowledge as Fact Units: atomic records of subject — predicate — object with a polarity, a content-addressed semantic fingerprint, a trust score, and one or more sources. The store is content-addressed and de-duplicated, so the same fact is never stored twice, and any answer can be traced back to the exact records that support it.

The guarantee that sets it apart: the Prime Directive (the gate). A question is answered only from retrieved, verified facts; if the store has nothing above the trust threshold, QueryBook returns UNKNOWN and declines — the “Without-Information Rule.” It cannot hallucinate a fact because it can only repeat what is stored and cited.

Install & run Built

QueryBook is dependency-free Python (standard library only). You need Python 3.8+.

  1. Unzip the QueryBook package to a folder.
  2. On Windows double-click START-WINDOWS.bat; on macOS run START-MAC.command. The launcher asks where to keep the store — pick an external drive if you plan to harvest at scale.
  3. Your browser opens to the Console. If it doesn't, go to http://127.0.0.1:8099/dashboard.

To run it by hand:

QB_DATA_DIR=/Volumes/MyDrive/qbstore  python3 qb_api.py
# then open http://127.0.0.1:8099/dashboard
Environment variableWhat it does
QB_DATA_DIRWhere the fact store lives (default ./mystore). Point it at an external drive for big harvests.

Harvesting facts Built

On the Console, the top bar runs harvests. Pick a domain, set a count (or use Run 24×7 for continuous), and press Start harvest. Harvesting is resuming: every run adds new facts — it never restarts from zero — and the tiles, charts, and “Harvest Workspace” update live from what's actually on disk.

Harvesting keeps the PC awake automatically while it runs, and releases that hold when it finishes (see 24×7 keep-awake).

Domains & the selector Built

The domain selector next to Start harvest lists only the domains that have a real generator behind them, read live from the engine (/api/domain_logic). Each domain has its own harvest logic:

DomainWhat it generates
mathematicsSquares, cubes, factorials, sums, products — grows without bound.
geometryCircle area/circumference, square area/perimeter by radius/side.
arithmeticTimes-tables (n × 1..12).

The Domain Navigator on the left shows every domain in the value model; the ones with a live engine (including the structural Language model) are marked live, the rest are Planned roadmap verticals. Dollar and percent figures there are illustrative planning estimates, not valuations.

Parallel harvesting. The “Parallel Domain Harvesting” card starts one agent per domain so they grow at once. On a single machine the total rate is shared across cores — running three domains doesn't triple throughput, it splits it.

Create a Fact Unit Built

The Create Fact Unit card adds your own fact. Fill subject, predicate, object, and a source label; QueryBook fingerprints, timestamps, and provenance-tags it exactly like a harvested fact (trust defaults to 0.9 for user entries). It's immediately queryable.

Verify & query Built

Type a subject (e.g. 144, circle radius 5) into Verify / Query to see exactly what is stored, with trust scores and fingerprints. This reads your real store — nothing is generated on the fly.

Grounded chat Built

The Chat screen runs the five-stage grounded pipeline:

  1. Plan — the question becomes one or more FQL query plans (subject / predicate / trust).
  2. Retrieve — QueryBook runs FQL over your store and returns ranked Fact Units.
  3. Gate — the Prime Directive classifies the result: VERIFIED, CONTRADICTED (competing values shown side by side), or UNKNOWN (refuse).
  4. Compose — an answer is written using only the gated facts, each cited [n].
  5. Check — every factual sentence must map to a cited fact; unsupported ones are flagged.

Without an API key, a deterministic composer answers straight from the facts (plain, still cited). With ANTHROPIC_API_KEY set, an LLM writes nicer prose — but is forbidden to add anything not in the facts. The answer always carries a response_provenance_hash.

Language Lab — learn & translate languages Built (deterministic)

The Language Lab (/language) is organized around one idea: English is the foundation language, learned in four phases; every other language is taught in one click. A legend at the top of the page shows which language each phase targets.

Teach QueryBook a language — one click

Pick a language in the “Teach QueryBook a language” card and press the button. QueryBook then does everything automatically — no agents to wire, nothing to run by hand:

  • Vocabulary — ~3,700–4,000 words per language from a bundled bilingual dictionary.
  • Pronunciation — IPA, syllables, and stress for every word (works with no install).
  • Translation — each word linked to its English meaning(s).

A live progress bar shows words learned / total, pronounced, and translated. The “All languages — status at a glance” table shows every language's readiness; press Teach on any row to build it.

Translate (auto-detects the source language)

The Translate card translates between English and any supported language. Leave From on Auto-detect and QueryBook senses the source language for you; pick the to language and press Translate. It is word-by-word from the dictionary — no LLM, no guessing: any word it doesn't know is left as-is and flagged, and it reports a coverage %. Press 🔊 Speak result to hear it. (Word-by-word means grammar isn't adjusted — e.g. Spanish el/la agreement — which is the honest limit of a dictionary translator.)

English — the four phases

English is learned in four phases, all built and deterministic (no LLM). Press “Build English — run all 4 phases” to run the whole pipeline automatically, or “Phase 1 only” to run just the first:

  • Phase 1 — Structural priming: grapheme inventory, rule-seeded phonemes, syllables, lexical stability, co-occurrence, pattern saturation; drives the one-way Transition Gate.
  • Phase 2 — Semantic grounding: grounds words from a bundled public-domain dictionary (Webster's 1913) and self-grounds against your verified store; every meaning carries a source.
  • Phase 3 — Multilingual delta / translation: maps English to/from other languages from the bundled bilingual dictionaries.
  • Phase 4 — Speech: pronunciation analysis (G2P phonemes, syllables, stress) and spoken audio through your computer's built-in voice.

Everything learned is written to the store as cited Fact Units in the language domain, so it's queryable like any other knowledge.

Speech — what needs no install, and what does

Pronunciation (IPA) always works, for every language, with no install. Spoken audio uses your computer's voices: English is always available; other languages speak in Chrome/Edge only if your system has that voice. For guaranteed offline audio in every language, install the free espeak-ng and QueryBook uses it automatically.

Diagnostics — if anything looks wrong

The Diagnostics card (and python qb_api.py diag) runs a full self-check: the dictionary source, the store and its index, a live write-and-read test, and an all-languages matrix (words, translation, pronunciation, speech per language). It lists any problems in plain words — press Copy report and send it if you need help.

Honest boundary. This is the deterministic prototype of the Language Expression Layer. Translation is dictionary word-by-word (demo bilingual data, MUSE, CC BY-NC) — accurate per word, but not grammar-aware; the trained neural model and neural vocoder remain the roadmap. The grapheme→phoneme map is rule-seeded; gate thresholds are the prototype calibration.

Agents & roles Built + roadmap roles

Agents are saved jobs that run on their own schedule (24×7) as background threads and survive restarts. Create one in the AI Harvesting Agents card by picking a role:

RoleDoesStatus
Domain harvester (deterministic)Grows a domain each cycle.Built
Web harvester (web)Politely crawls seed URLs, extracts Fact Units.Built
Grounded Q&A (grounded_qa)Answers a saved question each cycle; records verdict, citations; refuses on unknown.Built
Watch (watch)Re-answers a standing question and flags when the verdict/answer changes as facts arrive.Built
Reasoning / Hypothesis / PlannerGated reasoning, creative hypotheses, NLPL task planning.Roadmap

For Grounded Q&A and Watch, the “target” is the question. Roadmap roles are honest stubs: they refuse to run and name the engine they need, rather than faking it.

24×7 keep-awake Built

The 💤 24×7 Awake button is a master switch that keeps the PC awake in all modes — harvesting, paused, or idle — until you turn it off (it persists across restarts). A watchdog writes a heartbeat to keepawake.log, so if the screen went black you can tell whether the machine actually slept (a time gap in the log) or the display just turned off (no gap). Harvests and agents also engage keep-awake automatically while they work.

Connecting an LLM (optional) Built

QueryBook never needs an LLM, but you can attach one to write better chat prose or help a web agent extract facts. In the LLM Providers card use ⚡ Quick add — Claude and pick a model (Haiku by default; switchable to Opus, Sonnet, Fable). The API key is read from the ANTHROPIC_API_KEY environment variable only — QueryBook never stores your key.

Base URL for Anthropic is https://api.anthropic.com/v1. The provider preset fills this in for you.

Troubleshooting

“store dir not found” / stats error

You haven't harvested yet, or QB_DATA_DIR points somewhere empty. Start a harvest, or set the variable to your store.

Chat says UNKNOWN for everything

That's the Prime Directive working: your store has no verified fact for the question. Harvest the relevant domain or add facts, then ask again. UNKNOWN is honesty, not an error.

The screen went black — did it sleep?

Open keepawake.log in your store folder. A jump in the timestamps means a real sleep; steady heartbeats mean only the display turned off. Turn on 24×7 Awake to prevent sleep entirely.

A URL won't fetch in the Language Lab

Some sites block automated requests or need a login. Try another source, or paste the text directly. QueryBook fetches one page you choose — it does not crawl.
