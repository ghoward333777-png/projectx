QUERYBOOK — the suite: Language & Speech, Math/Science/Engineering, History & News, Video Studio, and the Control Panel
=======================================================================================================================
One package, five programs: four sharing one fact store (the Commons), plus the Video Studio. October 2026 release.

INSTALL
  1. Unzip this file anywhere (Desktop, Documents, a USB drive).
  2. Python 3.8 or newer is needed (https://www.python.org/downloads/ — on Windows tick
     "Add python.exe to PATH"). Nothing else to install: standard Python only.
  3. Start:
       Windows: double-click START-ALL-WINDOWS.bat     (or START-WINDOWS.bat inside one application's folder)
       Mac:     double-click START-ALL-MAC.command     (first time: right-click -> Open -> Open)
       Any:     python app.py   inside an application's folder
     Control Panel (one page for all three): START-CONTROL-PANEL-WINDOWS.bat / START-CONTROL-PANEL-MAC.command
       QueryBook Control Panel       http://127.0.0.1:8100/
     Each application opens in your browser and keeps its window open while you use it:
       Language Builder              http://127.0.0.1:8101/
       Math, Science & Engineering   http://127.0.0.1:8102/
       History & News                http://127.0.0.1:8103/
       Video Studio                  http://127.0.0.1:8104/   (needs ffmpeg; uses Language Builder for voices and narrators)
  4. Your data lives OUTSIDE these folders (~/QueryBook-Data/...), so installing a newer version over
     this one never touches it. To upgrade: close the applications, unzip the new version, start again.

HARVESTING — QUICK START (Control Panel, http://127.0.0.1:8100/)
  1. Keys: API & connections -> Google one-click setup (Google's own sign-in page; needs gcloud installed), and
     API registration for the other services (Sign up -> paste key -> Save & check). A personal package installs its keys
     by itself on first start.
  2. Bulk harvesting -> ⚡ Full speed (no passphrase needed unless you set one): every approved dataset (all of Wikidata in 16 lanes,
     PubChem, NCBI Taxonomy, NOAA weather, USGS places, USDA foods, Tatoeba, MIT OpenCourseWare, the calendar scaffold),
     one agent per CPU core. Duplicates are removed across all shards when the agents finish; agents pause if the disk
     has under 10 GB free.
  3. Coverage map (same tab): the 20 keystone domains, facts held in each, growing or saturated; the prototype's Hot
     Map (people, organisations, laws, medical, places, events) comes first.
  4. Fact gatherer (same tab): ask a question or fill open recurring-event slots. An LLM with web search only finds;
     QueryBook keeps a fact only when the page it returned states it.
  5. The live ticker under the tabs shows the fact counts and a progress bar for every harvest running.
  Rules everywhere: approved sources only, facts never generated by a model, every fact traceable to its source.

EXTRAS (QueryBook/extras)

  * exemplar-generator/answer_videos.py — answer videos: each line built from a sourced fact, checked word for word

  * QUESTION-TEMPLATES.md — the 461 question patterns QueryBook expects most.
  * device-bridges, visual-speech-engine-stage2 — as before.

WHAT'S NEW IN THIS RELEASE
  Backups to another drive, and safeguards for the saved facts (Control Panel 1.36.0, bulk engine 1.34.0)
    * Bulk harvesting -> Backups: type a folder on another drive (e.g. the new 40 TB drive) and Save. Every saved fact is then
      copied there once a day while harvesting (or press Back up now): every bulk dataset, the shared folder and the
      applications' own data. Each database copy is checked before the backup counts; a backup that did not finish never
      counts as one. Datasets that have not changed since the last backup are not copied again.
    * The newest 7 backups are kept, and so is the fullest copy each dataset ever had: a dataset that shrinks can always be
      brought back. A backup that finds a dataset smaller than last time says so on the page.
    * "Add back from the newest backup" adds back every fact the live datasets lack (nothing is deleted). The newest backup is
      also one of the copies checked at every Start, so missing facts come back by themselves while the drive is connected.
    * The copier never replaces the data drive's copy of a dataset with one holding fewer facts.
    * While facts are being added back at Start, the page shows the dataset's full count with a note, never a drop
      (on 8 November the page showed 206 million facts "lost" for a while: they were being restored, nothing was deleted).
    * Command line: python _core/qbvault.py backup --commons <shared folder> --to F:\QB-Backup
  Bulk harvesting no longer slows to a stop as the shards grow (Control Panel 1.35.2, bulk engine 1.33.0)
    * Each batch of 500,000 facts used to go straight into the shard's fingerprint index. Once a Wikidata lane held tens
      of millions of facts, every batch read and rewrote gigabytes; the writes outlasted the 15-minute stall limit, the
      agent was ended, its batch lost and its part read again from the start, over and over: most lanes showed
      0 facts/min. Now a batch is appended in about a third of a second, and the facts join the index in one sorted pass
      at the end of each part (or sooner when many are waiting). Measured on 25 million facts: about a sixth of the disk
      reading and writing.
    * An agent busy writing is no longer taken for stalled and restarted.
    * The facts-per-minute figures count facts the moment they are written; Look up finds them after each part's pass.
    * The speed shown for a running lane is measured up to now (a stuck lane no longer shows its last "10 MB/s"), and
      the overall percentage counts only the current dump edition (lanes no longer read 100% on file 5 of 9).
    * The engine version changed: press ⚡ Start harvesting once after installing, so the new engine replaces the old one.
  The Wikidata lanes no longer sit idle while the dump downloads (Control Panel 1.35.1, bulk engine 1.32.0)
    * Since 1.31 all 16 Wikidata lanes waited, producing nothing, until the whole 157 GB dump had downloaded and passed
      its checksum. When the download was slow or kept being refused, the harvest fell to a trickle. Now the lanes
      stream over the internet meanwhile and switch to the downloaded copy once it is ready; parts already done while
      streaming are not read again.
    * The download and the streaming lanes share each server's connection limit (Wikimedia two, the mirrors three or
      four), so together they never pass it, and a server's "slow down" rests both.
    * To wait for the download as before: setting bulk:wikidata:while_downloading = wait.
    * The engine version changed: press ⚡ Start harvesting once after installing, so the new engine replaces the old one.
  Network memory: learning connections between agents (Control Panel 1.35.0; also in the QueryBook 9.64 prototype)
    * The relationships between agents are now a layer of memory (shared module qbsynapse). Each synapse records its
      type, strength, activation threshold (higher when it has been unreliable), the contexts it formed in, good and
      bad outcomes, the last evidence and its history. Joint success strengthens it, joint failure weakens it, unused
      synapses fade and are removed, long-proven ones are consolidated; a new one starts weak.
    * Agents bound by strong synapses form assemblies; assemblies linked through their members form networks of
      networks; each kind of problem keeps its engram (the agents active when it was solved).
    * Where it learns: dataset stores that answer the same lookup (and the DSN asks a strong store's assembly partners
      first when its pathways find nothing); checks one application's team asks of another (a directed relationship,
      strengthened by an answer, weakened by "cannot check"). In the prototype: the specialists whose facts answer a
      question, and harvesting agents that succeed together — see its new Network page.
    * Control Panel: Harvesting -> Answer routing shows both networks (assemblies, strongest synapses); the health
      report adds a Network memory line. Answers and facts are never changed by the network.
  Answer routing: Central, Shadow or DSN (Control Panel 1.34.0; the bulk engine is unchanged at 1.31.2)
    * Bulk harvesting -> Answer routing (below Look up bulk facts) has three settings:
        Central  every store is asked in turn — the default, and the fastest on one computer in the stress test.
        Shadow   Central answers; the Digital Synaptic Network (DSN) answers the same lookup in the background and every
                 difference is written to the Shadow comparison log (shards/_dsn-shadow.jsonl).
        DSN      only the stores its learned pathways point to are asked; when those find nothing, every store is asked,
                 so routing never hides a fact.
    * The health report (📋 Health report, and the emailed one) now says which routing is on and, for the last 24 hours,
      how many lookups Shadow compared, how often the DSN agreed, where it missed facts, how many stores each asked and
      how long each took — with a verdict: keep Central, or DSN is safe to try (only after 50 lookups or more).
    * Learned pathways hold routes, never facts (shards/_dsn.json), and each one shows its strength, facts found and empty
      answers. Switching the DSN back on after Central pulls every pathway halfway back to neutral, so routes learned on
      an older set of stores are re-checked rather than trusted. Changing the setting uses the admin passphrase (if set).
  Stop that stops, Start that waits, and missing facts found and restored (Control Panel 1.33.2, bulk engine 1.31.2)
    * Stop: the agents end after their current batch (any still running after a minute is ended, the Wikidata download
      too); then only the copies that CHANGED are saved to D:, with "◐ stopping: saving … (n of N)" on the page. Before,
      Stop gave everything 60 seconds and then ended the engine in the middle of saving and of the duplicate check, which
      on a USB drive takes far longer. The duplicate check no longer runs at Stop (it runs in quiet hours). The button
      answers at once, even when D: is busy.
    * Start while a stop is still saving: harvesting starts by itself as soon as the save is done. It no longer clears
      the Stop signal under agents that are still running, so old and new agents never work side by side.
    * 🔎 Find and restore missing facts (Harvesting page, and by itself at every Start): every copy of every dataset is
      compared — the working copy on C:, the copy on D:, and the shared folders of earlier versions — and every fact a
      copy holds that the live one lacks is added back. Nothing is ever deleted. (The drop from 864.8 to 734.8 million was
      three whole datasets — NOAA 89.5 M, USDA FoodData 31.4 M, NCBI Taxonomy 8.9 M — no longer counted; if their facts
      are on any of these drives, this brings them back.)
    * A dataset whose file is busy at the moment the page restarts is shown with its last count (kept on disk), never 0.
    * The Download once panel shows the last try and why (it said "not started" even when a try had failed).
  The data drive no longer holds the harvest up (Control Panel 1.33.1, bulk engine 1.31.1)
    * Found: every 10 minutes the copier rewrote EVERY working copy on C: to D: in full (338 GB in all, PubChem alone
      51 GB), even copies that had not changed. A USB hard drive needs far longer than 10 minutes for that, so D: never

  Download once, read locally: the Wikidata harvest without the wait (Control Panel 1.33.0, bulk engine 1.31.0)
    * The weekly Wikidata dump (about 157 GB) is now downloaded ONCE to a drive, then all 16 lanes read it from there at
      disk speed. Before, each lane fetched its own part over the internet; the servers allow only a few connections
      per computer, so 13 of 16 lanes waited and a restarted lane began its part again (about 1 million facts an hour).

    * The lanes wait for it (they look again every 2 minutes), then read the copy. Work already done while streaming the
      same edition is kept (the parts have the same names). Every fact still names the publisher's edition date.
    * Control Panel → Harvesting → ⬇ Download once: progress, speed, time left, bytes from each server, the ready edition

  Speech science; any language; LLM subscriptions & usage (Language Builder 1.51.0, Control Panel 1.32.0)
    * Speak any language: Language Builder → Speech science → 1. The bundled espeak-ng now has all 112 pronunciation
      dictionaries (was 17): type text, the language is detected from its writing system or grammar words (or pick it),
      Speak, Download WAV, with the pronunciation (IPA) shown. Offline.
    * Read the lips of a talking head: choose a video → Read the words. The lips are read (with the look-alike words for
      each), the sound too when Speech-to-Text is set up. Every frame of the file is read by seeking, so a slow computer
      never skips frames and the same file always gives the same frames.
    * Measure a delivery (Speech Science Protocol SSP-1): about 20 movement factors of the lips, jaw, brows, cheeks,
      eyes and head, measured for every sound and word against what is said; Articulation Conformance (a z-score
      formula per sound), Naturalness (human-limit checks: lips that stay shut, move faster than human lips, open
      wider than a mouth can ...), A/V sync, intelligibility, and one Delivery Index. Pass/fail against criteria fixed
      in advance; a criterion whose instrument is not yet validated is reported as exploratory and does not decide the
      verdict. (1.52: talking clips are measured the same way.) Each delivery gets a report
      (Markdown + JSON) with the words, sounds, factors, why it failed, methods and limitations.
    * Compare dialects, accents and emotions: label deliveries, then compare groups clip by clip - 95% confidence
      intervals, Hedges' g, Welch's t-test with Holm correction, a leave-one-clip-out check that the difference is real;
      groups with fewer than 5 clips are reported but not interpreted. Deliveries marked "reference" calibrate the
      expectations for their language.
    * Control Panel → API & connections → API registration → 💳 LLM subscriptions & usage: every call any program
      makes to an LLM or paid AI service (Gemini, OpenAI, Anthropic, Perplexity, cloud voices, Speech-to-Text, video
      generation) with its time, tokens in/out, characters or minutes, result and estimated charge; per service this
      month; your plan, monthly fee, renewal date and budget per service (budget used in %); the last 30 days; every
      call, exported as CSV; editable prices. Charges are estimates from list prices - the provider's bill is
      authoritative (linked). No key, prompt or answer is stored.
