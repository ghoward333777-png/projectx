Google — one-click setup

Connects all six Google services (Gemini, Speech-to-Text, Text-to-Speech, YouTube, backups, health reports) for every QueryBook application at once. A Google sign-in page opens on this computer: choose your account and press Allow — that is Google's own page, your password never reaches QueryBook. Then it switches on the APIs, creates a QueryBook key restricted to them and saves it everywhere. Safe to press again (after adding billing, for example). Needs Google's free command-line tool (gcloud).

API registration — every service that needs a key

For each service: press Sign up (a G means you can use Sign in with Google there), create a key on its page, paste it here and press Save & check. QueryBook checks the key with one free request and keeps it privately on this computer, where every program reads it. You sign up and accept each service's terms yourself. The admin passphrase (box above) is asked once one is set.

Outside connections

Bulk harvesting

The fast lane: each open dataset is one agent that streams the publisher's whole file and turns every row into facts by a fixed rule — no AI model, only sources approved in the policy registry, every fact traceable to its file and row. Agents work in parallel, each into its own shard, and resume where they stopped. The calendar scaffold computes what can be known in advance; the recurring-event slots are filled from Wikidata, one query per series.

Coverage map — 20 keystone domains

What the harvest should cover, measured: facts held per domain (shards and shared facts), the sources feeding it, novelty (new facts per record read, from the harvest log) and the state. Bulk agents start in this order — the Control Panel's target first, then foundational domains (phase 0) and those unlocking the most, the least covered first. Saturated: under 1% new over a million records read.

Fact gatherer — LLM web search, checked on the page

An LLM with web search only finds: QueryBook fetches the pages the search returned and keeps a fact only when the page itself states it next to its subject (and, for relations like winner or born, with the right words in the right order). Each confirming site is the fact's source; two sites make it corroborated. Runs spend on the provider's account, so starting needs the admin passphrase.

Help

Start the panel with START-CONTROL-PANEL (or python app.py in its folder). It finds the three applications on this computer and can start them.

  • Overview — each application's state, version, health, harvest switch, facts and last harvest turn; alerts and monitoring.
  • Mass harvesting — start or stop harvesting everywhere, or a selection of applications and online harvesters.
  • Targeting / Filtering — global rules every application obeys from its next harvest turn. They need the admin passphrase once the admin has set one.
  • Assistant — type plain requests ("stop all harvesting", "focus on volcanoes in history", "exclude football", "find Marie Curie", "any alerts?"). It works by fixed rules (no AI model): it does only what it recognises, says what it changed, and asks before stopping anything.
  • Transparency — every action is in the audit trail; every harvest turn reports how many facts the filter left out and which tasks the target moved first.
