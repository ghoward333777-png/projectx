Book I · Doctrine

1. The Fact Unit

The fundamental data primitive of the QueryBook system is the Fact Unit: a discrete, atomic, provenance-tracked knowledge record, identified by a Fact Unit Identifier (FUID) deterministically derived from the record’s content, source, and ingestion timestamp. Each Fact Unit carries a confidence value, a safety classification, a language-independent semantic fingerprint, an embedding representation, temporal anchoring, and a reference into a provenance chain, and is immutable once created — a revision produces a new, linked version rather than modifying the existing record.

The confidence value is not a scalar. It is maintained as a first parameter accumulating evidence supporting the assertion and a second accumulating evidence contradicting it, the reported confidence being the ratio of the first to their sum, and their sum constituting the evidential weight from which a credible interval and a propagation precision are computed. The contributed weight is further attributed across registered source classes, from which a diversity measure is computed. Two records reporting an identical confidence and resting on different quantities or varieties of evidence are therefore distinguishable, which a scalar could not express.

Three properties follow from the schema. Safety classification and entitlement are fields rather than layers, so no code path reaches an assertion without them and rights enforcement is structural rather than best-effort. And the assertion is one assertion: a passage stating three things becomes three records, which is what permits a response to cite the specific claim it relied upon rather than the paragraph containing it.

2. Event Fact Units

An event fact unit is an ordinary Fact Unit whose type reference resolves into the governed event type catalogue — the event half of the governed event and entity type catalogue named in the schema above. The advanced specification, carried at Chapter 104 of the specification and inventoried as features 153–155 in Book II, adds four disciplines an event record obeys beyond the base schema.

2.1 The governed event type catalogue — §104.2

Every event type is registered on the same discipline as the predicate catalogue: an immutable identifier assigned at registration, a poly-hierarchical placement within the Ontology Mesh, a semantic definition stating both coverage and exclusions, a machine definition enumerating required, optional and forbidden fields, versioning permitting narrowing only, and deprecation rather than deletion. An event record is validated against its type’s machine definition at construction; a candidate carrying a forbidden field, or lacking a required one, is refused rather than admitted and flagged.

2.2 Environment vectors — §104.3

The conditions under which an event occurred are carried as an environment vector, content-addressed by a condition hash and bearing its own confidence, provenance and attestation time. The vector attaches through an annotation set, so no schema field is added to the Fact Unit itself, and correction proceeds by supersession, propagating to every referencing record. Two events recorded under identical conditions therefore share one environment vector by address, and a corrected condition corrects every event that cited it.

2.3 Causal edge temporal validation — §104.4

A causal edge between two event records is admitted only where the asserted cause temporally precedes the asserted effect under both records’ temporal anchors. An edge failing the validation is refused; an edge whose ordering cannot be established is not resolved by assumption. This is the structural guard that keeps the causal graph of the World-View Model consistent with the timeline the event records themselves attest.

2.4 Tri-temporal anchoring and admissibility

An event record distinguishes three timestamps: when the event occurred (the temporal anchor), when the record was ingested, and when its source was created (the attestation time). The third governs admissibility to retrospective analysis under the attestation horizon constraint (§103.3): a record is admissible to a pre-event snapshot only where its attestation precedes the event by the configured horizon, an unknown attestation excluding the record rather than being estimated. Query-time posture is tri-temporal (§123.2): attested past, live present, or projected future — a projected result carries a credible interval, is never admitted as a record, and never grounds a subsequent answer. Timeline reconstruction (feature 007) assembles event records into ordered narrative under these anchors, and the coherence classification’s temporal dimension (§124.1) reports, never gates, on the result.

4. Developmental sequence & the Transition Gate

[L07] Phase 1 (structural-acoustic): sound discrimination -> syllabic segmentation ->

[L08] The Transition Gate is one-way; opens only when all four thresholds are met. Each is

defined operationally [audit-fix] with a calibratable target; a no-convergence fallback

semantic inventory. Cross-language semantic alignments bridge L2 items to existing concepts.

[L10] Acquisition cost GENERALLY decreases with each language (the flywheel). [audit-fix]

Directional, not strictly monotonic: negative-transfer cases between specific language

calibration; (6) self-monitoring feedback loop ("babbling" analogue) against a defined

Grounded agent roles on the AgentManager

1. Governing principle

[A01] A QueryBook agent is not "an LLM agent." It is the grounded version of an agent role: whatever the role, every factual output is retrieved from verified Fact Units, cited, and refused when unknown; ambiguous steps halt instead of guessing; runs are reproducible and auditable. The failure modes of generic LLM agents — hallucination, error-compounding across steps, unauditable trajectories — are removed by construction, not patched.

2. The framework

[A02] All roles run on the existing AgentManager (qb_agents.py): a saved job with kind, target, interval, chunk, controlled by start / pause / stop / resume / delete, persisted to <store>/agents.json, run as daemon threads, holding the machine awake only while working. Multiple agents run concurrently = the multi-agent substrate. A role is a kind plus its loop behavior; the catalog is exposed at GET /api/agent_roles.

3. The grounded agent roles

Standard LLM agent type → QueryBook grounded role (kind) → status:

  • Reactive → Grounded Q&A (grounded_qa) — built: plan→retrieve→gate→compose→check on a saved question; cited answer + verdict; refuses on unknown.

  • Task / goal-oriented → NLPL planner (planner) — roadmap: decompose an instruction into operational intents; halt on ambiguity.

Amendment — Language Understanding Uses No LLM (2026-09-29)

Additive covenant to the Language Architecture chapter

Additive. The Language Architecture chapter above (the full neural LEL of record) stands unchanged. This amendment records what the QueryBook prototype (the “Language Lab”) has reduced to practice, and a hard covenant governing it.

Reduced to practice. Phase 1 (structural priming) learns the structure of English deterministically — grapheme inventory, rule-seeded grapheme-to-phoneme approximation, syllabification, lexical stability, co-occurrence density, prosody proxies — storing every measurement as a provenance-tracked Fact Unit while semantics are suppressed, and driving the four Transition-Gate thresholds to a one-way latch. Phase 2 (semantic grounding) attaches meaning deterministically from two auditable sources: a bundled public-domain dictionary (Webster’s 1913) and self-grounding against the verified Fact Unit store. Every meaning carries a source that can be checked.

The covenant — no LLM in language understanding. QueryBook acquires and performs language understanding (Phases 1–2) without any large language model. The LEL learns its own parameters bottom-up; grounding is deterministic. An LLM is excluded from the language-understanding and grounding path. This is enforced in code by qb_language.LLM_LOCKOUT = True, which drops any “suggestor” callable while set. The rationale is the Prime Directive itself: a live provider check proves a connection works, never that a returned meaning is true, so an LLM meaning cannot satisfy the provenance mandate. A future dictionary-gated suggestor may only propose a meaning that is accepted solely where it agrees with the public-domain dictionary, which remains the authority.

Scope — what the lockout does and does not cover. The covenant governs language understanding, meaning-grounding, and fact assertion: there, no LLM is used, and no asserted fact originates from an LLM. An LLM remains available in strictly non-asserting roles: (i) phrasing — narrating an answer over facts the system has already verified; and (ii) hypothesis and simulation — proposing candidate ideas and driving exploratory simulations. In every such role the LLM never establishes truth; anything it proposes is admitted only after independent verification against the deterministic store (and a grounding suggestor only where it agrees with the public-domain dictionary). Put plainly: an LLM may help QueryBook speak and wonder, never decide what is true.

Amendment — The Reasoning Family of Agents (2026-09-29)

Hypothesis, simulation, and gated reasoning — reduced to practice

Additive. Three reasoning-family agents are now built in the prototype, each obeying the covenant above.

Hypothesis and simulation agents let an LLM wonder: the hypothesis agent proposes candidate facts, the simulation agent projects a scenario’s consequences. Every candidate is verified against the deterministic store — corroborated, contradicted, or open — and stored isolated at low trust in a hypothesis or simulation domain. Nothing either proposes is ever returned as a verified fact.

Gated reasoning — the one place inference may assert. Deduction asserts, but only truth-preserving transitive closure over verified premises: where X P Y and Y P Z are both verified and P is a transitive relation, the engine asserts X P Z into a derived domain, carrying both premises as provenance, with trust decaying each hop so chains terminate. This is sound because the conclusion is entailed by facts already verified — a proof, not a guess — and it uses no LLM. Induction and abduction only propose, as non-asserting candidates verified against the store. The Prime Directive holds: the engine asserts only what it can prove or has independently verified.

Gate note. The answer gate now treats multi-valued relations (is_a, part_of, located_in, …) as corroborating facets rather than contradictions, so a subject may soundly hold several such objects at once; functional relations still flag genuine contradictions.

Planner (NLPL). A planner agent decomposes a goal into ordered operational intents and halts on ambiguity — for an underspecified goal it returns one clarifying question and stops, rather than inventing a plan. A plan is a proposal, stored non-asserting in a plan domain; it asserts no facts.

Phase 3 — multilingual delta (deterministic). The Delta Acquisition Model is now approximated deterministically and without an LLM: the engine reuses the English foundation of Phase 1 and learns only the delta to a second language — the word mapping — from a bundled bilingual dictionary, stored as translation_<lang> Fact Units with an auditable source. Spanish and French ship as demonstration targets. The bundled bilingual data is a demo set (CC BY-NC) to be replaced with a public-domain/permissive source before commercial use, and the full neural cross-lingual alignment remains the roadmap embodiment. Only Phase 4 (speech output) now remains roadmap.
